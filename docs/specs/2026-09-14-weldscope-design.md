# WeldScope — Design v0.1

> In-process OCT for laser welding quality monitoring — a Rust real-time pipeline,
> Python test harness, and an interactive Three.js + WASM documentation site.
> Portfolio system to demonstrate what is achievable with Rust + AI in the
> industrial OCT sensor domain.

## 1. Goal & Scope

Pipeline that mirrors a production in-process OCT weld monitor (class of systems:
Precitec IDM, IPG weld monitoring): an OCT depth sensor observes the laser keyhole
during welding; the system extracts the **keyhole depth trace** in real time from
interferometric spectra and turns it into a **weld-quality verdict**
(penetration, spatter, pores, humping).

Non-goals (deliberate, explicit):
- No real sensor hardware interface (only a `TcpSource` stub as the plug-in point).
- No GPU pipeline, no Docker, no metrics dashboard, no database.
- ONNX inference is feature-gated (`onnx`), not the default.
- Public dataset is **synthetic but physically consistent** (interferometric
  spectra generated by inverse-FT of a designed depth-reflectivity profile).
  Real in-process weld OCT data is proprietary (no public dataset exists —
  verified via GitHub searches, 2026-09).

## 2. Architecture

Rust workspace; each module is a crate and a separate process, connected by a
documented binary TCP wire format (length-prefixed frames).

```
acq ──[spectrum frames @100 kHz]─→ core ──[depth trace]─→ features ──[feature vec]─→ ai ──[verdict]─→ sink/log
     \____________________ TCP (binary, length-prefixed) + latency stamps ____________________/
```

Modules:
- `acq` (binary) — simulated sensor source; ring buffer; emits spectrum frames
  with sequence number + timestamp. Abstract `Source` trait with `SimSource` and
  `FileSource` (replay); real sensor plugs in later behind the same trait.
- `core` (lib) — SD-OCT signal pipeline + keyhole depth extraction. Pure,
  unit-testable, compiles to WASM.
- `features` (lib) — physics-based quality features from the depth trace.
- `ai` (lib) — embedded weights (JSON) inference with zero runtime deps;
  feature-gated ONNX path via `ort`.
- `io` (lib+binary) — TCP framing, sequence/latency stamps.
- `weldscope` (binary) — orchestrator: spawn/stop modules, fault injection hook.

Python harness (`harness/`) starts the system, asserts verdicts, measures
latency, runs soak and regression tests.

Web (`web/`) is the public gh-pages showcase: Three.js + the `core` crate
compiled to WASM + detailed workflow documentation.

## 3. Data flow & wire format

- Frames: little-endian, magic `WS01`, version, sequence number, type, timestamp,
  payload. Versioned and documented in `docs/wire-format.md` — itself the
  deliverable for the JD item "define performant data interfaces between
  system components".
- Transport: stdlib TCP (no ZeroMQ dependency). ZMQ/DDS behind the same framing
  is a later, non-breaking option.
- Latency: frames carry stage timestamps; the harness measures end-to-end
  (frame sent → verdict received) and reports p50/p99.

## 4. Core: FFT pipeline (physically consistent)

- Simulator emits interferometric spectra = inverse-FT of a designed depth
  reflectivity profile `r(z)` (keyhole surface as a peak at depth `z_t`, melt-pool
  scattering noise, pores as echoes) + DC + shot noise. The FFT genuinely
  recovers `r(z)` — same data path in native and WASM.
- Pipeline (measured on this machine, 2026-09): `BG-sub → k-resample
  (precomputed grid) → Hann (precomputed) → zero-pad → realfft → power → log →
  keyhole peak detection (gated max + center-of-mass, sub-pixel)`. realfft
  4096-pt R2C ≈ 4 µs/A-scan ≈ 250 kHz single-core; full chain with power+LUT
  log ≈ 65 kHz single-thread — meets clinical/industrial real-time.
- Keyhole dynamics model (literature-grounded): nominal depth + kHz-range
  oscillation + seeded defects:
  - spatter → spike
  - pore → step/tail (bubble transient)
  - incomplete penetration → depth ramp down
  - humping → periodic dropout
- Per-stage latency stamps; the same `core` code runs native and in WASM.

## 5. AI module (hybrid)

- Core: documented feature formulas (depth mean/variance/min, penetration state
  with hysteresis, event rates) → logistic regression / small MLP; weights from
  JSON → inference with zero runtime dependencies, fully reproducible.
- Optional: `onnx` feature compiles the `ort` path for bring-your-own models.
- Output: verdict (OK / SPATTER / PORE / INCOMPLETE_PENETRATION / HUMPING) +
  confidence.

## 6. Python harness (JD: tests, stability, regression)

- Golden tests: N seeded welds → verdicts == ground-truth defect schedule.
- Latency report p50/p99 end-to-end.
- Soak: continuous run, assert no crashes and bounded frame loss.
- Fault injection: kill/restart modules via orchestrator; assert recovery.

## 7. Web / gh-pages (Three.js + WASM + docs)

- Interactive canonical visualization: embedded dataset → WASM `core` runs the
  FFT in-browser → Three.js renders (a) A-scan depth profile, (b) B-scan weld
  cross-section, (c) keyhole depth trace with defect markers.
- Workflow docs in detail: FFT principle (interactive: k-resampling,
  zero-padding, window before/after), signal path diagram, architecture,
  real-time metrics, defect types, AI, tests.
- Deploy via GitHub Actions to Pages.
- Optional labeled rendering showcase: public *medical* OCT volume (from the
  oct-research corpus, e.g. ROSE / OCTDL) as volume-rendering demo only — never
  presented as weld data.

## 9. Milestones (each individually demoable)

1. Workspace + acq + core: FFT on simulated spectra → depth trace (CSV) —
   proves the signal chain.
2. features + ai: verdicts + ground-truth dataset — proves the quality
   assessment.
3. io framing + multi-process + latency stamps — proves the system.
4. Python harness: golden / latency / soak / regression — proves stability.
5. web: WASM + Three.js + docs + Pages deploy — the showcase.

## 10. Decisions & rationale

- TCP stdlib framing over ZeroMQ: zero native deps, fully testable, versioned
  wire format is itself a deliverable; ZMQ is a drop-in transport later.
- Simulated-but-physically-consistent data: no public weld OCT dataset exists;
  a simulator demonstrates domain understanding and produces a reproducible
  ground-truth benchmark dataset.
- Embedded JSON weights over deep learning as default: honest on synthetic
  data, real-time, reproducible; ONNX path proves model interchangeability.
- Separate processes (not threads): genuinely shows "parallel distribution to
  multiple processing modules" and enables real fault injection.
